# Grindset v1.0.0

First personal-use release of Grindset, formerly Lockin. This is not a store-reviewed release or a guarantee of uninterrupted background enforcement.

## Downloads

- **Windows x64 installer:** `grindset-1.0.0-windows-x64-setup.exe`. Per-user installation; no administrator access required. The installer is unsigned, so Windows may show trust warnings. Do not disable Defender or other security protections.
- **Windows portable:** `grindset-1.0.0-windows-x64-portable.zip`. Extract the complete folder and run `lockin.exe`; the executable's legacy name is intentional.
- **Android ARM64:** `grindset-1.0.0-android-arm64.apk`. Signed with the retained owner key. Updates require the same package/signing identity and a higher version code. Debug previews use a different signing identity; do not uninstall a personal installation without preserving its data.
- **Chrome/Edge extension:** `grindset-1.0.0-browser-extension.zip`. Extract, open `chrome://extensions` or `edge://extensions`, enable Developer Mode and load the extracted folder. Pair using the six-digit code in Grindset Settings. The Windows app must remain running.
- `SHA256SUMS.txt` provides download checksums; `android-signing-certificate.txt` records the public APK certificate.

## Included

- Minimal focus/break timers with restoration, shared sessions and union-accounted history.
- Individual activity budgets, schedules, optional focus restrictions and source-specific five-minute overrides.
- Opt-in native Windows and Android tracking, Android Accessibility blocking, and paired Chrome/Edge website restrictions.
- Local SQLite history, private export/reset, account-bound Supabase sync and explicit offline conflict handling.
- Grindset branding across the app, Android service/accessibility labels, tray, notifications, installer, shortcuts and extension.

Actual Chrome and Edge blocking/override flows and the patched Android identifier-entry form passed native acceptance. CI checks do not establish physical-device reliability.

## Known limitations

- Physical Android/OEM reliability testing is deferred. Force-stop, permissions and OS/battery restrictions can interrupt collection, enforcement and notifications.
- Visible Windows completion notification delivery remains **unverified**. Scheduling/cancellation passed; an uncertain sighting was not counted as a pass.
- Email confirmation can finish on an unavailable localhost redirect. Confirmation itself succeeds; return to the app and sign in. An app-owned redirect destination remains outstanding.
- Native Edge accounting, desktop-player/screen-lock boundaries, Android post-reset redownload and some installed recovery/onboarding paths remain unverified. See the README and platform evidence documents.
- Website blocking requires the connected extension. Enforcement is voluntary, not tamper-proof. Public distribution still requires privacy/policy review.

## Compatibility

The legacy app/package IDs, executable/resource/storage identifiers, startup key, export format and signing key are unchanged so branding does not strand existing history, authentication or updates. Historical evidence and SDK/signing-backup paths intentionally retain the former name. Existing Windows installations retain their install directory; new installations use `Programs\Grindset`. The repository remains private.
